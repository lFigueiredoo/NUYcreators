## 2. Proteção local preparada

O ID de produção conhecido foi registrado como constante não secreta em `src/lib/env/protected-project.ts`. `assertDedicatedProject` agora bloqueia esse ID **antes de qualquer requisição**, mesmo com `APPWRITE_EXPECTED_PROJECT_ID` igual e `APPWRITE_TEST_ENVIRONMENT=staging`. O guard já era usado por `infra:preflight`, `infra:plan:remote`, `infra:apply`, deploy de Functions e suites de integração/QA; as sondas `infra:capabilities` e `infra:scopes` também passam pelo guard. O runtime Next rejeita `VERCEL_ENV=preview` se receber o ID protegido. O caminho Production do runtime não foi mudado.

Continuam obrigatórios os gates anteriores: endpoint HTTPS `/v1`, Project ID esperado configurado **independentemente**, confirmação do projeto dedicado, ambiente `development`/`staging`, identidade do marker privado, chave aceita no projeto correto e distinção entre chaves. O preflight verifica provisionamento, Auth e chave de teste quando configurada; `infra:scopes` verifica operação e mídia. A checagem de chave é feita pelo Appwrite com `X-Appwrite-Project`; comparar nomes ou copiar uma chave de produção não é prova. Nenhum fallback para produção foi criado. Os guards preparados localmente **não protegem deployments Vercel já publicados**, pois não houve deploy.

**Limite da proteção:** o ID protegido é um retrato da produção atual. Se Production migrar para outro projeto, essa constante e os testes precisam ser atualizados **antes** de qualquer QA. A verificação final também deve comparar o novo ID com a configuração Production vigente no Console/Vercel, não confiar apenas na constante.

Verificação local desta preparação: **55 testes focados passaram**, `tsc --noEmit` passou e os arquivos editados passaram no Prettier. A execução direta de `npm run infra:preflight` neste sandbox parou no carregador `tsx/esbuild` com `spawn EPERM`, **antes do código do preflight e antes de qualquer chamada de rede**; portanto não é evidência de preflight remoto. O teste unitário de identidade confirmou que o ID protegido é rejeitado antes de `fetch`. Repetir o CLI em ambiente operacional apropriado quando houver novo staging.
